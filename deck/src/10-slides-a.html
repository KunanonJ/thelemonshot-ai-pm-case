Task 1 · Why these three

One loop, three flywheels

Data flywheel

Every campaign writes outcomes, including sales, back to one creator graph. Better matches lead to better results, more campaigns and more data.

Adoption flywheel

Proposal Copilot builds the habit in Slack, Sheets and Slides. Match and Pulse ship into the same surface, so there is almost no new workflow to learn.

Capability flywheel

Each build reuses the data mart, prompt library, error-handling templates, evals and governance, so it ships faster than the last.

Why it fits a service agency

It covers win rate (Proposal), results and retention (Match) and margin per head (all three). Time saved becomes capacity for more pitches, not smaller invoices.

The combination matters more than any single tool. Every shortlist and every campaign writes to one creator performance graph. Adoption compounds too, because each tool lands in the same Slack and Sheets surface. And for a service business: more wins, better results, more output per head. One caveat: if clients pay by the hour, efficiency can cut revenue, so this pushes us toward retainer or value pricing.

Task 1 · Deprioritized, not dismissed

Year 2: not no, not yet

Three department heads asked for these. None gets its own build in Phase 1, but each gets something now and a clear trigger for when we start.

Creator RMN fails gate

Why not now

A data product with no data foundation, no engineers and no partner contracts yet.

Now · no extra build

Commerce attribution inside Pulse. A PDPA data-sharing framework. Retail clients such as Lotus's and makro as design partners. A business case at month 6.

Start when

6+ months of creator-to-sales data across 50+ campaigns, one retail data partner LOI, and approved engineering budget.

Trend Monitoring buy

Why not now

Commodity signals. The best data sits behind restricted APIs (TikTok's Research API excludes agencies). Indirect ROI.

Now · no extra build

Keep using existing tools such as TikTok Creative Center.

Start when

A two-vendor bake-off finds one with API access and PDPA-compliant terms. Its trend snapshot then plugs into Proposal Copilot.

DCO fails risk gate

Why not now

The highest likeness and IP risk, and the strongest creative resistance. Platforms already ship gen-AI creative tools.

Now · no extra build

A pilot of platform-native tools on product-only assets. A draft AI Likeness Rider and consent registry.

Start when

Pilot creators sign the rider, governance is approved, and a CD sponsors it.

None of these three gets its own build in Phase 1. Saying no to a department head works better when they get something now and know exactly what would change the answer. For RMN, Phase 1 builds the three assets it needs. For Trend Monitoring we buy, we don't build, and a vendor bake-off is how Year 2 starts. DCO waits for likeness governance, because launching it first would poison trust in everything else.
