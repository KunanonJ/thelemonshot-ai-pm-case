FEEDBACK LOOPEvery keep and remove, every override reason, and every campaign outcome flows back to BigQuery, which drives better weights, prompts and evals.
Why these models

Thai-language quality, proven on our eval set, not assumed. Reliable JSON via structured outputs. No open-source models in v1: self-hosting them needs engineers we don't have.

Why n8n

Self-hosted, so data stays under our control (PDPA). Code nodes and Slack approvals built in. Make bills per module run, so a loop over 60 creators multiplies cost. LangChain needs engineers.

Design rule

The model is a config value. The data model is the asset. Prompts and schemas are versioned, and vendors can change without a rebuild.

Five layers, left to right. Public metrics need no consent; audience demographics need the creator's own OAuth grant, which is why Creator House onboarding is on the critical path. BigQuery is the only place scoring reads from, so API changes never break scoring. Models are swappable; our data model is the asset. If asked about alternatives: Make would work and the logic carries over, but it bills per module run. LangChain is a code framework, so it needs engineers we don't have. Open-source models become an option in Year 2 if cost or data residency calls for them.
Task 2 · The exact logic in n8n

CM-01: brief to shortlist in about 20 nodes

1 · Intake

Form Trigger, or a PDF via Extract From File. Then HTTP POST api.anthropic.com/v1/messages with claude-sonnet-5-5 and output_config.format set to a JSON schema. Code validates the result; gaps go back to the requester through Slack Send and Wait. On error, the fallback is OpenAI /v1/responses.

2 · Retrieve and score

BigQuery GoogleSQL applies the hard rules: platform, consent, not blocked, no competitor work in 90 days. Code scores performance (Bayesian-shrunk history plus engagement vs tier), audience fit and cost per engagement. CM-02 refreshes stale profiles.

3 · Judge

One Claude call per creator, in batches of 5, 1 s apart. It returns brand fit 0-100, a rationale citing posts, risk flags and confidence. A failed call becomes "not assessed" and never blocks the shortlist.

4 · Deliver and learn

Weights by objective, budget fit, at least one rising creator, flags shown and never dropped. Then Drive copy and Sheets, then Slack Send and Wait (approval, restricted approvers), then Proposal Copilot. Every decision is logged to BigQuery.

This is the exact flow I'd configure, and the importable workflow exists with demo data. Hard rules run in SQL before any AI. The LLM does two narrow jobs: parse the brief and judge brand fit, both with a JSON schema so the output is machine-checkable. Everything that leaves the system goes through a human approval in Slack.
